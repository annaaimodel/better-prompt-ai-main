# CV Tool — Build Spec (v2)

**Date:** 2026-06-12
**Decisions locked:** Free & public (no accounts) · In-browser CV handling · Claude **Sonnet 4.6** · **Nothing about a CV/JD is ever stored**
**Status:** **Phase 1 shipped** (`/cv`, live) · Phases 2–3 specced below.

---

## 1. What it does (user's view)

1. User lands on **`/cv`**, pastes or uploads their CV (PDF/DOCX/TXT) — parsed **in their browser**.
2. **[LIVE] Match:** it scores their CV against the live job list (`jobs/store.json`) **in the browser** and shows the best-fit roles ≥ a threshold (default 80%), with the reason + matched terms.
3. **[Phase 2] Paste any job description** — including roles we can't access (gated FB/Skool posts, jobs not on the board). Works for *any* JD because the user supplies it.
4. **[Phase 2] A few tailored questions appear** — partly fixed, partly generated by Claude from that specific JD (e.g. it catches "record a 2-min Loom about a deal you saved" and asks about one).
5. **[Phase 2] User gets two deliverables for that role:**
   - a **tailored cover letter**, and
   - a **personalised Loom video script** (timed, in their voice, with talking-point bullets).
6. They copy/download. **Nothing is saved anywhere.**

---

## 2. Privacy by design (unchanged across phases)

| Step | Where the data is | Stored? |
|---|---|---|
| CV upload / paste / parse | User's browser only | ❌ never |
| Match vs jobs | User's browser | ❌ never |
| JD paste + question answers | User's browser until they click generate | ❌ never |
| Cover letter / Loom script generation | Sent **once**, in-memory, to a stateless function → Claude → returned | ❌ never (no DB, no disk, no request-body logging) |

- No accounts, no database, no file storage, no logging of CV/JD/answers.
- **Anthropic Zero-Data-Retention (ZDR)** on the API org/key so even Anthropic retains nothing.
- One-paragraph privacy notice on the page (already present on `/cv`).

**GDPR result:** no stored personal data → minimal footprint, no CV/JD breach surface.

## 3. Architecture (bolts onto the existing static site)

```
 Browser  /cv  (static page)                         Vercel serverless fns (stateless)
 ┌───────────────────────────────┐                  ┌────────────────────────────────────┐
 │ CV parse (pdf.js / mammoth)    │                  │ POST /api/role-questions           │
 │ match vs /jobs/store.json      │  [LIVE, no AI]   │  in: {cv_summary, jd}               │
 │ ── paste any JD ───────────────│ ───────────────► │  out: 3–6 tailored questions        │
 │ answer questions               │                  │                                    │
 │ ── generate ───────────────────│ ───────────────► │ POST /api/cover-letter             │
 │ show cover letter + Loom script│ ◄─────────────── │  in: {cv, jd, answers}              │
 │ copy / download                │                  │ POST /api/loom-script              │
 └───────────────────────────────┘                  │  • Claude Sonnet 4.6 (ZDR)          │
                                                     │  • returns text · logs/stores nothing│
                                                     └────────────────────────────────────┘
```

- **Frontend:** the existing `/cv` page gains a "Paste a job description" box + a questions step + a results step. Same style.
- **Backend:** small stateless serverless functions. One AI call each; the question-generator is a cheap pre-step.
- **Job data:** `/jobs/store.json` (already generated daily) for matching. Cover letter/Loom work on *any* pasted JD, on or off the board.

## 4. The question flow (the clever bit)

**Hybrid: a short fixed core + Claude-generated, JD-specific questions.**

- **Fixed core (always asked):** name, years in sales, niches/industries closed, best result/proof point, availability/timezone, CRM/tools.
- **Dynamic (Claude reads the JD → 3–6 targeted questions),** e.g.:
  - JD sells $8k coaching → "Highest-ticket offer you've closed + your best number?"
  - JD requires Spanish → "Confirm fluent Spanish — mention it?"
  - JD says *"record a 2-min Loom on why you'd be great"* → "Any specific win/story you want featured in the video?"

Answers feed **both** the cover letter and the Loom script, so the user fills them once.

### Loom script output shape
Hook → who you are → 1–2 *relevant* proofs from the CV → why this company/role → directly address the JD's explicit asks → confident close/CTA.
Returned as: the spoken script (~60–90s, UK English, their voice) **+** talking-point bullets **+** light timing markers.

### Cover letter output shape
~250–350 words, confident, UK English, tailored to the JD, leaning on the CV + answers. Copy/download.

## 5. Cost model (Sonnet 4.6 — $3 / $15 per 1M in/out)

| Item | Cost |
|---|---|
| CV parsing + matching | **$0** (in browser) |
| Question generation (`/api/role-questions`, ~3k in + ~400 out) | **~$0.015** |
| Cover letter (~2k in + ~600 out) | **~$0.013** |
| Loom script (~5k in + ~800 out) | **~$0.027** |
| **Full set for one role (questions + letter + script)** | **~$0.05** |
| 1,000 full sets / month | **~$55** |
| Vercel | Hobby free now; **$20/mo** Pro when commercial |
| Database / storage | **$0** (there is none) |

**The real risk on a free public AI endpoint is abuse, not unit cost.** Required guards (cheap, standard):
- **Bot check** on the generate calls — Cloudflare Turnstile / hCaptcha (free).
- **Per-IP rate limit** (e.g. 5–10 generations/hour) via Upstash Redis or Vercel KV (free tier).
- **Input caps** — reject CV/JD over N characters.
- **Hard monthly spend cap** on the Anthropic key.

## 6. Build phases

**Phase 1 — Matcher (no AI, $0): ✅ SHIPPED.**
`/cv` page · PDF/DOCX/TXT parse in browser · fetch `jobs/store.json` · score & show ≥threshold matches with reasons. Linked in site nav.

**Phase 2 — Generators (cover letter + Loom script):**
"Paste a job description" box · `/api/role-questions` (dynamic + fixed questions) · answer step · `/api/cover-letter` + `/api/loom-script` (Sonnet 4.6, ZDR, zero logging) · copy/download.

**Phase 3 — Abuse protection + polish:**
Turnstile + per-IP rate limit + input caps + spend cap · cross-links from `/jobs` and the main site · styling pass.

**Rough effort:** Phase 2 ~half a day · Phase 3 ~half a day.

## 7. Open items before / during Phase 2

- **Anthropic API key** with **ZDR enabled**, set as a Vercel env var (never in client code). *Needed before Phase 2 can run.*
- Serverless runtime: **Node** (simplest on Vercel) or **Python** (reuse the Anthropic SDK pattern). Default Node unless preferred otherwise.
- Loom script length/tone defaults (~60–90s, confident, UK English) and cover-letter length (~250–350 words).
- Whether to gate behind a paywall later — bolts on at the `/api` layer **without** changing the no-storage design.
- For the CV→server payload: send the full CV text, or a small in-browser-extracted summary, to keep prompts tight (and even more privacy-minimal).
